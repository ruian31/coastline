# 03 · 技术方案与适配

版本：0.1 · 日期：2026-10-21 · 状态：技术基线；M4持续迭代中

## 1. 技术路线

采用 TypeScript、Vite 与 Three.js 实现客户端浏览器游戏。第一版无需账号系统或业务后端，偏好和探索记录保存在本机浏览器；清除浏览器存储会重置这些记录。

工程依赖锁已修复，当前 TypeScript 与生产构建通过，9 项桌面/手机尺寸的 Chrome/WebKit 行为测试通过。更广泛浏览器与真实手机兼容仍需按验收补充。

客户端使用固定物理步长更新驾驶，渲染按实际帧率运行。初期采用适合轻度驾驶的定制运动学车辆与简化碰撞，不直接追求完整汽车动力学。若原型无法满足坡道与碰撞需求，再评估专门物理引擎。

## 2. 模块边界

```text
src/
├── core/          # 循环、输入意图、渲染器、质量设置、资源生命周期
├── game/          # 状态、驾驶模式、探索进度与暂停/恢复
├── world/         # 道路图、地形、海面、建筑、植被、地标与碰撞代理
├── vehicles/      # 三款车的模型、内饰、配置和状态驱动部件
├── systems/       # 驾驶、自动巡航、摄像机、音频、地图与界面
└── utils/         # 数学、可复现随机数、资源清理
```

模块命名是目标结构。已清理与驾驶无关的通用演示，当前主循环位于 `src/game/OceanDrive.ts`。

**更新顺序：** 输入意图 → 固定步长驾驶/碰撞 → 地点与模式状态 → 车辆可视部件 → 镜头/声音/界面 → 渲染。

键盘、鼠标和手机触控产生同一种输入意图，不在不同设备上各写一套驾驶规则。

## 3. 道路与驾驶

- 道路使用连续曲线描述中心线、高度与路宽，并预采样供路面生成、定位和自动驾驶复用。
- 岔路通过道路图和连接点表达，允许双向通行；避免只用单一环形参数限制所有移动。
- 手动驾驶在世界坐标中运动，允许离开中心线、掉头和进入岔路。
- 使用简化的加速度、制动力、滚动阻力与速度相关转向；车轮与方向盘从同一状态取值。
- 路面高度、坡度和碰撞代理独立于视觉细节。建筑和护栏用简化形状碰撞，避免高细节网格碰撞成本。
- 固定更新步长以 1/60 秒为起点，限制单帧累积时间，防止切回页面后车辆突然前进。
- 路外降低抓地与速度，边缘保护防止跌入海中；返回道路选择最近的安全路面并清零危险速度。

## 4. 自动巡航与接管

自动巡航以道路图上的路径为目标，通过前视点计算转向，根据前方曲率调整目标速度。沿主环线能持续行驶，选择支路后也必须能正确并回主路。

主状态建议：`手动`、`自动`、`暂停`、`车辆切换中`。镜头状态独立维护，避免“电影视角”和“自动驾驶”在代码中成为无法拆开的同一个状态。

- 进入电影镜头触发自动模式，并更新界面。
- 明确的油门、制动或转向输入接管驾驶；电影镜头同时退出到安全驾驶视角。
- 切换普通视角不会无提示地取消自动巡航。
- 暂停恢复后保留原有模式，但清除旧按键和触控状态。
- 关闭页面或失去可见性后，停止模拟与声音；回到页面时等待明确恢复。

## 6. 手机浏览器

### 交互

- 左侧连续转向控制，右侧油门与刹车/倒车，另有清楚的手刹入口。
- 自动巡航时可收起大型驾驶控件，把空间让给风景，同时保留接管入口。
- 顶部或边缘提供视角、车辆、巡航和菜单；常用触控目标至少约 44 CSS 像素。
- 使用 Pointer Events 与指针捕获，正确处理抬手、取消、丢失捕获、页面失焦和切后台。
- 支持两根手指同时控制油门和方向，不依赖悬停、右键或键盘。
- 画面拖动用于观察，与固定触控区互不冲突；控制区使用合适的 `touch-action`。

### 布局

- 横屏优先；竖屏仍可玩，主路、车身和必要按钮保持可见。
- 适配刘海、安全区和动态地址栏，避免底部按钮被系统手势区域覆盖。
- 不强迫全屏或锁定方向；提供可选全屏按钮，并处理浏览器不支持的情况。
- 手机首次进入给简短操作引导，开车后收起说明。

### 兼容与降级

计划覆盖桌面 Chrome/Edge/Safari/Firefox，以及 Android Chrome 和 iOS Safari。具体版本与真实设备结果写入测试报告；当前没有完成这些兼容验证。

WebGL 不可用或上下文创建失败时显示清楚的恢复提示。处理上下文丢失、窗口缩放和横竖屏切换，避免只剩黑屏。

## 7. 性能目标与预算

以下为开发预算，不是当前实测结果。

| 指标 | 电脑目标 | 手机目标 |
| --- | --- | --- |
| 帧率 | 尽量稳定 60 FPS | 中档设备争取稳定 30 FPS 以上 |
| DPR 上限 | 初始 1.5–2，按实测调节 | 初始 1–1.5，按实测调节 |
| 单帧 draw calls | ≤300 | ≤150 |
| 可见三角形 | ≤750k | ≤300k |
| 活跃几何体 | ≤300 | ≤200 |
| 活跃纹理 | ≤60 | ≤40 |
| 动态阴影光源 | ≤2 | ≤1 |
| 阴影贴图边长 | ≤2048 | ≤1024 |
| 额外后期效果 | ≤2 道 | 0–1 道 |

优化顺序：先减少阴影与后期开销，再做实例化、可见性剔除与远景 LOD，最后降低远景密度。保留近处车辆内饰、关键植被运动、道路清晰度和海面光感。

自动质量可在持续低帧率后下降一个档位，避免每帧来回变化；用户可以手动选择流畅/标准/精致。必须分别实测车内、镇内、隧道出口等高负载场景。

## 8. 资源与声音

当前生成服务的凭据检查结果：3D、图像和音频生成服务均未配置可用密钥。这只影响资源制作方式，文档与原型可继续。

首选有意设计的程序化车模、内饰、场景套件、纹理和本地合成音乐/环境声；若后续获得适合的授权资源或生成能力，再替换对应表面。车辆精细度需要通过实际画面评审，不能因采用程序化方案就自动视为达标。

运行时不调用付费生成 API，不包含任何服务密钥。音频按用户手势解锁，音乐、发动机、环境声分组控制，暂停时清理或挂起，避免重复循环叠加。
