# 04 · 开发计划与验收

版本：0.1 · 日期：2026-10-21 · 状态：持续开发中，详见各阶段状态

## 1. 顺序与阶段

先把一个代表性瞬间做对，再扩展地图。里程碑按成果定义，不预先承诺未经评估的工期。

| 阶段 | 交付物 | 完成条件 | 当前状态 |
| --- | --- | --- | --- |
| M0 · 文档与项目归位 | 需求、世界视觉、技术、计划、决策记录 | 已确认要求可追溯，假设有标识，项目位于 workspace | 文档初稿完成 |
| M1 · 一段有感觉的海岸 | 一辆敞篷车、一段夕阳海路、基本内饰、手动与自动驾驶、三视角、手机基础控制 | 电脑与手机尺寸均可驾驶，能感知暖光、海面和绿植风动 | 已可玩；首轮双端测试通过，继续画面迭代 |
| M2 · 连通探索区域 | 主环线、相连支路、小镇、隧道、地标与简洁地图 | 实际从主路驶入支路并回归；隧道出口呈现海景；小镇可通行 | 未开始 |
| M3 · 三车与完整声音 | 三款不同车身与内饰、可动仪表和方向盘、音乐与环境声、设置 | 所有车可切换且可驾驶，声音状态和暂停/恢复正确 | 未开始 |

M1 即包含车内和电影视角，避免后期发现整车尺度、内饰布局或自动巡航无法支撑核心体验。M2 在 M1 的代表性场景通过评审后展开。

## 3. 画面与性能证据

完整版本至少保留以下实际场景证据，并记录视口尺寸、车型、镜头和驾驶模式：

1. 桌面第三人称：海岸弯道与完整车身。
2. 桌面车内：暖光、仪表、观察副驾与手刹。
3. 电影视角：自动驾驶的连续片段。
4. 隧道内至出口：包含明暗过渡与海景展开的连续片段。
5. 小镇与岔路：手动选择路线的操作过程。
6. 手机横屏：触控驾驶中的实际画面。
7. 手机竖屏：驾驶与菜单操作中的实际画面。
8. 三款车：同类机位对照，证明车身和内饰差异。

对应性能数据记录帧率、渲染调用、三角形、几何体、纹理、DPR、阴影和画质档位。浏览器设备模拟只能证明部分布局与交互，不能代替真实手机 GPU 性能和 iOS Safari 兼容验证。

## 4. 测试重点

### 开发验证

先修复初始化的依赖锁文件问题，再完成类型检查与生产构建。仅在对应模块进入开发后补行为测试，不为尚未实现的设计编写空测试。

重点自动化覆盖：驾驶状态转换、巡航/手动接管、暂停后输入清理、道路连接与恢复、车辆切换状态、声音生命周期、触控取消与横竖屏布局。

### 实际游玩

以真实键盘、鼠标与触控路径完成海岸 → 小镇 → 支路 → 隧道 → 返回出发点。检查刹车、倒车、不同车型、三视角、静音、暂停、重新进入和窗口尺寸变化。

这是一款放松探索游戏，不以竞争性通关、死亡重试或分数增长作为验收；等价的核心验证是路线选择、地标到访与卡住恢复。

## 5. 主要风险与应对

| 风险 | 提前验证 | 应对 |
| --- | --- | --- |
| 车内细节成本高、模型尺度不合适 | M1 就从驾驶位检查仪表、副驾与手刹 | 优先驾驶位可见面，精做一辆后扩展 |
| 手机容易因阴影、水面和植被掉帧 | M1 在手机尺寸测基础场景，M4 补真机 | 实例化、LOD、DPR与阴影降档，保留关键近景 |
| 自动驾驶在岔路/隧道失效 | M2 连续跑通相连道路 | 使用明确道路图，记录接管与路径状态 |
| 电影镜头穿模或引发眩晕 | 每加入一种地形就录制镜头通过 | 安全机位、遮挡检测、缓慢过渡与减少动态模式 |
| 地图做大但沿途缺乏变化 | M1 先做有感觉的小段，M2 检查景点节奏 | 按驾驶时间安排地标，缩小无意义空路 |
| 当前资源生成服务无凭据 | 已检查并记录在技术方案 | 采用有意设计的程序化资源，按实际效果评审 |

## 6. 交付报告要求

报告包含可玩地址/本地启动方式、操作、实现清单、实际执行的检查、桌面与手机证据、性能测量、尚未验证的设备与已知限制。不得把“可在手机打开”表述为“已验证所有手机流畅”。
